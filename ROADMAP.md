# Proxon module roadmap

## Initial plant and room functions

- **Implemented:** system status for operating modes, fan speeds/stages, air temperatures, connected room panels, sensor values and filter runtimes.
- **Implemented:** standard plant controls for operating mode, fan stage, cooling enable, intensive ventilation, CO2/RF thresholds and filter service values. Protective and tuning controls are tracked under the Advanced split below.
- **Already present:** configurator reads the connected NBP/HNBP bitfields and offers only detected room panels.
- **Implemented:** CO2/RF room assignment for up to five sensors. Panel temperature correction is now in the Advanced instance.
- **Evidence executed:** read-only review of the manually configured FWT Modbus devices in Symcon and comparison with the supplied register sheets. The corresponding function and register groups are now represented in the module.
- **Changed locally:** the Proxon 2 Central target-temperature slider now uses whole-degree steps and rounds action/API requests to whole degrees. The register's hundredth-degree format remains in place for readback.
- **Evidence executed:** Symcon TEST showed a 0.1 °C step before this change. During heating, 3x0069 decoded as Off; the user clarified that 3x0069 is a test/debug value and 4x0241 is the real heat-pump mode. No target write was performed. Confirm whole-degree input after updating Symcon.
- **Register conflict found:** a manually configured Symcon instance labels register 48 as the minimum outdoor temperature for cooling. The FWT 2.0 workbook defines register 46 for cooling enable temperature (5–20 °C) and register 48 for compressor operation independent of heat demand (−15–5 °C). The module now exposes both documented controls; the live manual instance was left untouched.
- **Status mapping implemented:** Input Register 4x0241 is the actual heat-pump mode; Symcon archive values and matching operating states confirm 0 = off, 1 = heating and 2 = cooling. Register 3x0069 remains test/debug only. Other 4x0241 codes stay unknown.
- **Open:** apply the local module update in Symcon and confirm the newly displayed values and write actions against the installation. No writes were issued to the existing live Modbus devices during this review.

## Standard and Advanced system control

- **Implemented locally:** separated daily controls and routine status values from compressor/heat-pump limits, airflow tuning, temperature-source selection, bypass temperature threshold and HNBP/NBP sensor correction. Advanced writes require the switch in System Control; the instance is created through its configuration button.
- **Implemented locally:** added read-only Bypass Status (FC4/register 222) and text Damper Position (FC4/register 159) to standard System Control. Position labels use the existing Symcon mapping for values 0–4.
- **Evidence executed:** inspected the PDF register entries and the configured read-only Modbus instances in Symcon. The bypass entry specifies `1 = open`; the damper entry identifies EG/OG distribution, while the existing Symcon presentation provides the five position labels. No writes or configuration changes were made to the live Modbus instances.
- **Migration:** variables for advanced controls already owned by System Control and Proxon Zone are retained, hidden and made read-only when those module instances apply the update; the Advanced instance owns the new controls.
- **Fixed locally:** replaced undefined `LOGMESSAGE_*` names with supported Symcon `KL_MESSAGE` and `KL_WARNING` constants in the System Control, Advanced and Zone modules. Source search confirms no `LOGMESSAGE_*` references remain; re-run the Advanced creation action in Symcon after updating the module.
- **Open:** the updated library has not been loaded into Symcon yet. Confirm polling, labels and action lockout after installing the update. Keep Advanced disabled unless these settings are required and understood.

## T300 control and Monitoring

- **Implemented locally:** split the T300 Holding Register controls and FC4 monitoring into separate device modules, following the FWT standard/Monitoring pattern. The control instance owns 14 workbook settings; the Monitoring instance owns the 57 read-only FC4 values, polled in seven register groups.
- **Implemented locally:** writes to the four settings confirmed by the existing Symcon configuration (registers 2000-2003) are enabled by default. The other ten candidate writes are read-only unless the user explicitly enables Advanced Controls. All writes are still range/type checked; no hardware write has been issued for the ten unverified registers.
- **Implemented locally:** added a configuration action to create the Monitoring sibling instance on the same Modbus parent. Monitoring uses the existing 60-second default, exposes an Update Values action, leaves archive settings to the user, and reports failed FC4 blocks in the debug window.
- **TEST evidence executed:** after the library update, both split instances were found active (status 102). Control exposes 14 settings, with four confirmed settings switchable and ten advanced candidates read-only; Monitoring exposes all 57 read-only values, all recently refreshed. Neither instance had archived variables or warnings/errors in its recent runtime log. No control write was sent.
- **Read-only parity check:** corrected temperature readings and several pressure, setpoint, tank-average, fan-speed, restart-count and timer values agree with the existing manual ModBus setup. The existing manual configuration and archive settings were left unchanged. Two dynamic readings were sampled at different poll times, so their comparison is inconclusive.
- **Validation:** the FC4 groups cover all 57 definitions exactly once; scaling retains explicit temperature offsets and defaults missing offsets to zero. Presentation `DIGITS` was removed because Symcon rejected it for this Value Presentation. Validation passed: all module/form/locale JSON parses, all module GUIDs are unique, the 57 FC4 definitions are covered once by seven groups, and PHP syntax parsing passed for both T300 module files. A TEST runtime check also confirmed active instances and fresh monitoring updates.
- **Open:** review the currently implausible External Sensor Temperature, Superheat Reference and Defrost Start Temperature values against the workbook and device configuration before treating them as valid measurements. Recheck the two dynamic readings with synchronized polls. The workbook's ten advanced candidates still need documented write permission and hardware verification on a dedicated test device; no write test has been performed. Register 861 fault labels, raw ADC channels and undocumented state codes also remain open. No visualization is included.
